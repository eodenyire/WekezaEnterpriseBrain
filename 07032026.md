## 🏗️ Datahub Architecture

The implementation (found in `migrations/001_CreateWekezaDataHub.sql`) is organized into four distinct schemas:

1. **`staging`**: Raw landing tables for each source system (7 tables total).
2. **`warehouse`**: Star schema optimized for query performance.
* **Dimensions:** `dim_customers` (GCID), `dim_accounts`, `dim_date`.
* **Facts:** `fact_transactions`, `fact_payments`, `fact_risk_assessments`, `fact_interactions`, `fact_cases`.


3. **`analytics`**: Data consumption layer.
* **Materialized Views:** `customer_360`, `daily_transaction_summary`, `risk_dashboard`.
* **Feature Store:** `customer_features` containing 35+ pre-computed ML features.


4. **`audit`**: `etl_sync_log` for tracking all pipeline executions.

### 🆔 Global Customer Identity (GCID)

The system implements identity resolution within `warehouse.dim_customers`.

* **Resolution Logic:** `national_id` → `email` → `phone`.
* **Function:** `warehouse.resolve_customer_gcid()` handles upsert-safe resolution across disparate systems.

## ⚙️ ETL & Orchestration

All ETL services support **incremental watermark loading** via `?since=<timestamp>`.

* **WekezaBankEtlService:** Maps channels (Mobile/ATM/Branch) and Tazama risk typologies.
* **WekezaOpenBankingEtlService:** Syncs transactions with 3rd-party attribution via `oauth_clients`.
* **WekezaCrmEtlService:** Connects to SQL Server via `Microsoft.Data.SqlClient`; performs sentiment analysis joins and SLA breach computation.
